## 当前网站的两套入口并不只是换语言

- **英文首页观察：** 浅色背景、居中宽度的主体；左侧圆形 HJ 头像，右侧姓名 / 身份简介，下方是代表书籍封面。[英文首页](https://kage-ai.com/)
- **中文首页观察：** 顶部白色导航，下方是深蓝紫色的大块简介区域；左侧黑白头像、右侧姓名简介，橙色身份文字；有 GitHub / 公众号 / 知识星球三个按钮，再下方回到浅色背景并展示代表书籍封面。[中文首页](https://kage-ai.com/zh/)

**推论：** 英文页更接近克制的作者主页；中文页首屏更强调专业身份和工作室入口。

**后续用户确认（2026-10-10）：** 选择“深色介绍区 + 浅色内容区”。这确定了明暗分区，不等同复制中文页的完整栏目或具体色值。最新状态以 [设计确认文档](../personal-website-design-brief.md) 为准。

### 英文首页：围绕个人观点和专业成果

**观察：** 顶部有 Writing、Concepts、Research、Books、About，以及 GitHub 和中文入口。主体先介绍本人和写作方向，再依次展示近期写作、代表概念、书籍、关于、Newsletter。书籍和订阅连接外部平台。[英文首页](https://kage-ai.com/)

**推论：** 这是“个人研究与创作门户”：访问者先明白作者研究什么，再看到相互关联的成果。它带来的价值是清楚定位和成果组织，而不是必须有某几个同名栏目。

### 中文首页：围绕中文作品与已有平台

**观察：** 中文页主体依次包含本人介绍、书籍、课程、案例、访谈、公众号、知识星球；书籍分中文与英文，课程分训练营、专栏与视频课，并提供相应资源或站外入口。中文页不等同于英文首页内容的逐段翻译。[中文首页](https://kage-ai.com/zh/)

**推论：** 这里更接近“个人工作室的作品陈列与对外入口”。它把已有作品、教学内容和渠道集中到本人名下，形成一张可信且具体的创作地图。本站可以借鉴这个入口关系，不能据此推定用户需要课程、书籍、付费社群或双语站。

## 内容如何被组织

| 栏目 | 当前可核实的组织方式 | 对本站的潜在借鉴 |
|---|---|---|
| [Writing](https://kage-ai.com/writing/) | 文章按日期列出，带简述；说明文章先发布于 Substack，本站作为规范档案 | 本人内容可以在站内保留长期地址，再连接其他发布渠道 |
| [Concepts](https://kage-ai.com/concepts/) | 少量代表性概念分别拥有固定 URL，供文章与演讲引用；页面说明概念从重复出现的想法中提炼 | 内容自然积累后建立主题页，而不是第一天就填满分类树 |
| [Research](https://kage-ai.com/research/) | 分 Frameworks、Reading Maps、Papers；项目带版本 / 年份、说明和入口 | 作品不只展示封面，也解释它是什么、解决什么、能去哪看 |
| [Books](https://kage-ai.com/books/) | 以英文 / 中文分组列出作品，附说明与出版社 / 购买入口 | 若以后有课程、文档、电子书等成果，可归入“作品”总结构 |
| [About](https://kage-ai.com/about/) | 职业背景之外，也解释另一段人生经历与创作之间的关系，并有联系方式 | 关于页可以展示“为什么我会做这些”，帮助形成个人辨识度 |
| [中文案例库](https://kage-ai.com/zh/cases/) | 行业场景与技术专题分开组织，提供案例和代码仓库入口 | 项目可以有多种标签或视图，不必强行归入唯一层级 |
| [中文访谈](https://kage-ai.com/zh/interviews/) | 文字访谈外链；视频内容以渠道入口补充，注明部分内容待补 | 其他网页入口可以按用途说明，避免只有平台图标 |

**观察补充：** 概念详情页具备面包屑、定义、问题、设计含义、来源脉络和进一步阅读，并给出可引用的固定地址。[概念页样本](https://kage-ai.com/concepts/model-spends-harness-budgets/)。文章页则显示作者、日期及原发布平台。[文章页样本](https://kage-ai.com/writing/build-me-an-agent.html)。因此，“主题页”和“一次写作的文章”是两种不同内容形式。

**推论：** 这对灵活扩展尤其有帮助：一篇文章可以保持自己的地址；多年围绕同一问题的文章又能汇集为一个主题页面。新增主题不会要求把旧内容搬到新地址。

## 对“个人工作室”的建议解释

**推论 / 建议：** 可以把它理解为“一个人持续生活、思考和创作的地方”：有明确的本人身份，有具体作品，有在做的事情，也有观察和日常。这样既能体现能力，也保留读者想再次回来看的个人内容。

建议组合：

1. **本人介绍采用 Anthony / pseudoyu 的直接与轻量。** 显示名字、短定位、正在做什么，不写没有证据的履历和数字。
2. **精选成果采用 kage-ai 的区块逻辑。** 展示 2–3 件最有代表性的作品，解释是什么并给出体验 / 详情入口。项目、文章、工具、文档都可以成为成果。
3. **最新记录采用 pseudoyu 的混合内容思路。** 生活、想法、项目进展可共存；内容形式与主题标签保持独立。
4. **其他网页入口放在有说明的模块中。** 比如项目体验、公众号、GitHub、摄影集、联系等；实际有哪些，以用户已有入口为准。
5. **长期主题页作为后续能力。** 仿照 Concepts 的稳定引用关系，在内容反复出现后再形成专题，不必把“观点”或“知识库”预造为必需栏目。

这组建议对应一个候选首页顺序：**我是谁 → 精选作品 → 最近记录 → 现在在做什么 → 我的其他入口**。它是讨论用方案，不是最终承诺；如果用户更重视最新内容，可交换精选作品与最近记录的位置。

## 应借鉴的原则与需要克制的地方

- **借鉴成果说明和入口，而非照搬职业栏目。** 本站若没有书、论文或课程，就让项目 / 文章承载同样的功能。
- **保持阅读内容的长期存在。** 外部平台可以帮助分发，个人站仍应有可持续引用的本人内容地址。具体发布方式以后确定。
- **已有内容决定导航。** kage-ai 建立了明确成果库；本站内容尚未清晰时，先以记录和项目作为宽容的入口即可。
- **明确个人工作室的口吻。** “个人工作室”不自动代表公司、团队、接商业委托或售卖产品；这些都需要用户另行确认。
- **避免从偏好推导过多功能。** 喜欢 kage-ai 不代表已批准双语、课程商城、邮件订阅、扫码社群或付费内容。
- **不要照搬待补占位块。** 案例库明确表示有部分方向预留。本站可保存扩展能力，但公开页面应优先呈现已有内容，避免空栏目压过真实内容。
